# Mototáxi da Cidade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sistema de mototáxi com três telas (passageiro, motoqueiro, central) rodando uma corrida completa em tempo real.

**Architecture:** Um servidor Node.js (Express + Socket.IO + SQLite) serve API, tempo real e as três telas estáticas. A lógica de negócio (preço, corrida, distribuição) fica em módulos sem dependência de HTTP, ligados por um barramento de eventos (`EventEmitter`) que o módulo de tempo real retransmite aos clientes.

**Tech Stack:** Node.js 22, express, socket.io, better-sqlite3, bcryptjs, jsonwebtoken, Leaflet (CDN), `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-11-mototaxi-design.md`

## Global Constraints

- Todo texto visível ao usuário em português do Brasil; valores em `R$ 0,00`.
- Papéis: `passenger`, `driver`, `admin`. Status do motoqueiro: `pending`, `approved`, `blocked`.
- Status da corrida: `searching`, `accepted`, `arrived`, `in_progress`, `completed`, `cancelled`, `no_drivers`.
- Padrões: `base_fare` 3.00, `per_km` 2.00, `min_fare` 6.00, `commission_percent` 10, `offer_timeout_s` 20.
- Preço arredondado para múltiplos de R$ 0,50; calculado só no servidor.
- Motoqueiro só recebe oferta se: aprovado, online, sem corrida ativa, posição nos últimos 120 s.
- JWT com validade de 30 dias; senha com bcrypt; mínimo 6 caracteres.
- Erros da API: JSON `{ "error": "mensagem" }` com código HTTP adequado.
- Sem etapa de build no frontend; módulos ES nativos.
- Segredos só por variável de ambiente (`JWT_SECRET`, `ADMIN_PHONE`, `ADMIN_PASSWORD`); `.env` e `data/` no `.gitignore`.

## Review Focus

1. Dois motoqueiros aceitam a mesma corrida quase juntos → só o primeiro fica com ela; o segundo recebe erro claro. (Task 5)
2. Serviço de rota (OSRM) fora do ar ou lento → corrida ainda é criada com distância estimada, sem travar mais de 4 s. (Task 2)
3. Motoqueiro perde a internet com corrida aceita → corrida continua dele; ao reconectar a tela restaura o estado; a central pode cancelar/reatribuir. (Tasks 4, 6, 10)
4. Passageiro toca duas vezes em "Pedir" → só uma corrida ativa é criada. (Task 4)
5. Telefone digitado com máscara, espaços ou +55 → mesmo usuário no cadastro e no login. (Task 3)

### Task 4: Ciclo da corrida

**Files:** Create `server/rides.js`, `tests/rides.test.js`.

**Interfaces — Consumes:** `openDb`, `getSettings`, `calcPrice`, `AppError`, `validCoord`.
**Produces:** `createRideService({ db, bus })` →
- `createRide({ passengerId?, passengerName, passengerPhone, origin: {text,lat,lng}, dest: {text,lat,lng}, distanceKm, payment: 'cash'|'pix', notes?, source: 'app'|'central', driverId? }): Ride` — grava preço; status `searching`; emite `bus.emit('ride:searching', { ride, driverId })` e `ride:update`. Passageiro com corrida ativa → `AppError(409)`.
- `getRide(id): Ride | null` — inclui `driver: { id, name, phone, plate, moto_model, lat, lng } | null`.
- `activeRideFor(user): Ride | null` (passageiro ou motoqueiro).
- `assignDriver(rideId, driverId): Ride` — só de `searching`; `UPDATE ... WHERE status='searching'` e checar `changes === 1`, senão `AppError(409, 'Corrida já foi aceita por outro motoqueiro')`.
- `act(rideId, action: 'arrive'|'start'|'complete'|'cancel', actor: { id, role }, reason?): Ride` — `arrive`: accepted→arrived; `start`: arrived→in_progress; `complete`: in_progress→completed (só o motoqueiro da corrida ou admin). `cancel`: passageiro dono até `arrived`; admin em qualquer status ativo; motoqueiro da corrida até `arrived` → corrida volta a `searching`, `driver_id = null`, emite `ride:searching` de novo. Transição inválida → `AppError(409)`; ator sem permissão → `AppError(403)`.
- `markNoDrivers(rideId)`: searching→no_drivers. `retry(rideId, driverId?)`: no_drivers→searching, emite `ride:searching`.
- `rate(rideId, passengerId, rating 1..5)`: só `completed`, uma vez.
- `list({ passengerId?, driverId?, status?, from?, to?, limit = 50 }): Ride[]`.
- Toda mudança emite `bus.emit('ride:update', ride)`.

- [ ] **Step 1: Testes:** caminho feliz completo com timestamps preenchidos; preço gravado = `calcPrice`; segunda corrida do mesmo passageiro → 409; `start` antes de `arrive` → 409; outro motoqueiro tenta `arrive` → 403; passageiro cancela em `in_progress` → 409; motoqueiro cancela em `accepted` → status `searching`, `driver_id` nulo, evento `ride:searching` emitido; `assignDriver` duas vezes → segunda 409; `rate` 6 → 400, duas vezes → 409; coordenada inválida → 400.

### Task 5: Distribuição

**Files:** Create `server/dispatch.js`, `tests/dispatch.test.js`.

**Interfaces — Consumes:** `rides.assignDriver`, `rides.markNoDrivers`, `haversineKm`, `getSettings`.
**Produces:** `createDispatcher({ db, bus, rides, now = Date.now, schedule = setTimeout })` →
- escuta `ride:searching` e chama `offerNext(rideId, driverId?)`;
- `candidates(ride): Array<{ driverId, km }>` — regra dos Global Constraints, exclui quem tem oferta `declined`/`expired` para a corrida, ordena por distância;
- `offerNext(rideId, onlyDriverId?)` — cria `ride_offers` `pending`, emite `bus.emit('ride:offer', { offerId, driverId, ride, timeoutS })`, agenda `expire`. Sem candidato → `rides.markNoDrivers`. Com `onlyDriverId` oferece só a ele (mesmo ocupado? não: precisa estar aprovado e sem corrida ativa, senão `AppError(409)`).
- `respond(offerId, driverId, accept: boolean): Ride` — oferta precisa ser `pending` e do motoqueiro; aceitar → `rides.assignDriver`, oferta `accepted`; recusar → `declined` e `offerNext`. Emite `bus.emit('ride:offer_closed', { offerId, driverId })`.
- `expire(offerId)` — se ainda `pending`: `expired`, `ride:offer_closed`, `offerNext`.
- `stop()` — limpa temporizadores (para testes e desligamento).
- Corrida cancelada com oferta pendente → oferta vira `expired` e `ride:offer_closed` (escutar `ride:update`).

- [ ] **Step 1: Testes** (com `schedule` falso que guarda callbacks): oferece ao mais próximo; ignora offline, pendente, bloqueado, ocupado e posição com mais de 120 s; recusa → vai para o segundo; `expire` → vai para o segundo; todos recusam → `no_drivers`; atribuição manual oferece só ao escolhido; aceitar oferta expirada → 409; aceitar oferta de outro motoqueiro → 403; corrida cancelada fecha a oferta; dois `respond(accept)` para a mesma corrida → o segundo lança 409 e a corrida fica com o primeiro.
